我们在不同的命名空间下，实例和配置都是相互之间隔离的，我们也可以在配置文件中指定当前的命名空间。

## 配置环境划分

在实际开发中，为了将服务注册到指定的命名空间（如开发环境 dev），我们需要在微服务的配置文件中进行显式指定。

**注意：** 在配置文件中填写的是命名空间的 **ID**，而不是名称。例如 dev 环境的 ID 为 `3a7d168f-1b05-452b-bdb8-af9b64edcab1`。

修改 `application.yml` 配置示例如下：

```yaml
spring:
  application:
    name: bookservice
  datasource:
    url: jdbc:mysql://localhost:3306/cloudstudy?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=UTC
    username: root
    password: niuniu0626
    driver-class-name: com.mysql.cj.jdbc.Driver
  cloud:
    nacos:
      discovery:
        server-addr: localhost:8848
        # 指定命名空间 ID，实现环境隔离
        namespace: 3a7d168f-1b05-452b-bdb8-af9b64edcab1

mybatis:
  mapper-locations: classpath:mapper/*Mapper.xml
  type-aliases-package: com.example.common.entity
```

通过这种方式，`bookservice` 服务在启动后就会自动注册到 Nacos 的 `dev` 命名空间下，而不会干扰 `public`（公共）或其他命名空间中的服务。

## 1.1 Nacos 集群架构设计与高可用逻辑

### 1.1.1 为什么要搞集群（高可用性）
在生产环境下，单机版 Nacos 存在“单点故障”风险。如果只有一台服务器，一旦它宕机，所有微服务将无法注册或获取配置。
**高可用（High Availability）** 的本质就是通过部署多个 Nacos 节点（集群），确保其中一个节点倒下时，其他节点能立即接管工作，保证系统永不掉线。

> **注意：** Nacos 集群比较消耗内存（建议 2 个节点至少分配 2G 内存）。由于部分架构限制，本节以 Linux 云主机环境进行演示。

### 1.1.2 Nacos 集群的三种访问模式
官方推荐在所有 Nacos 节点前搭建一个负载均衡器。根据连接方式的不同，分为以下三种模式：

![deployDnsVipMode.jpg](https://s2.loli.net/2023/03/06/H1AvxOK78yspP5k.jpg)

1. **直连 IP 模式 (`http://ip1:port/openAPI`)**
   - **逻辑：** 微服务直接在配置文件里写死某一个 Nacos 节点的 IP。
   - **弊端：** 灵活性差。如果这台指定的机器挂了，即使集群里其他机器还活着，微服务也连不上，必须手动修改代码中的 IP。

2. **挂载 SLB 模式 (`http://SLB:port/openAPI`)**
   - **逻辑：** 在所有 Nacos 节点前放一个“前台接待”（SLB/负载均衡器，如 Nginx）。微服务只找这个接待员。
   - **优势：** 接待员会自动判断哪个 Nacos 节点活着并转发请求。即便某个 Nacos 节点挂了，对微服务也是透明的。
   - **弊端：** 虽然解决了 Nacos 宕机的问题，但你的代码里写死了“接待员”的 IP。**万一有一天机房搬迁，“接待员”换了个 IP，你还得去改所有微服务的代码重启**，很麻烦

3. **域名 + SLB 模式 (`http://nacos.com:port/openAPI`) —— 官方推荐**
   - **逻辑：** 在接待员（SLB）之上再加一层 DNS（域名解析）。微服务只记录一个永久不变的网址（如 `nacos.example.com`）。
   - **优势：** 极高的灵活性。无论后端 Nacos 节点怎么换，甚至负载均衡器的 IP 变了，只需要修改 DNS 解析记录，微服务的代码一行都不用改。

### 1.1.3 负载均衡与信息同步
在一个集群中，微服务只需要在 **任意一台** Nacos 节点上注册，Nacos 内部会自动将这些信息同步给集群内的其他节点。为了实现对外统一访问，本笔记后续将使用 **Nginx** 作为 SLB（服务器负载均衡器）来转发流量。

## 1.2 Nacos 统一数据存储 (MySQL)

在集群模式下，多个 Nacos 节点必须共享同一份数据，否则会出现配置不一致的问题。Nacos 3.x 默认使用 MySQL 作为外部存储。

### 1.2.1 数据库初始化
1.  **创建数据库**：在 MySQL 中创建名为 `nacos` 的数据库，字符集选择 `utf8mb4`。
2.  **执行脚本**：从 Nacos 安装目录的 `conf` 文件夹下找到 `mysql-schema.sql`（注意：3.x 版本文件名已更新）。
3.  **验证结果**：执行脚本后，数据库中应生成 `config_info`、`users`、`permissions` 等核心表。

## 1.3 Nacos 服务端集群配置 (核心实操)

针对 Nacos 3.2+ 版本，我们需要对运行环境和配置文件进行多项关键调整。

### 1.3.1 环境要求
* **JDK 版本**：必须安装并使用 **JDK 17** 或更高版本（3.x 强依赖）。
* **内存优化**：若本地内存有限，修改 `bin/startup.sh` 或 `startup.cmd` 中的 JVM 参数（如 `-Xms512m -Xmx512m`）。

### 1.3.2 节点 A 与 节点 B 的配置
我们需要准备两个 Nacos 目录（如 `nacos-server-A` 和 `nacos-server-B`），分别修改其 `conf/application.properties`：

```properties
#*************** 基础端口配置 ***************#
# 节点 A 设为 8801，节点 B 设为 8802
nacos.server.main.port=8801

#*************** 数据库配置 (3.x 适配) ***************#
# 3.x 版本切换 MySQL 的关键开关
spring.sql.init.platform=mysql
db.num=1

# 数据库连接地址 (指向 nacos 库)
db.url.0=jdbc:mysql://localhost:3306/nacos?characterEncoding=utf8&connectTimeout=1000&socketTimeout=3000&autoReconnect=true&useUnicode=true&useSSL=false&serverTimezone=UTC
db.user=root
db.password=niuniu0626
db.pool.config.driverClassName=com.mysql.cj.jdbc.Driver

#*************** 鉴权安全配置 ***************#
# 3.x 要求即使关闭鉴权，也必须配置长度不低于 32 位的密钥
nacos.core.auth.enabled=false
nacos.core.auth.plugin.nacos.token.secret.key=VGhpc0lzQU1vY2tTZWNyZXRLZXlUaGF0SXNTdWZmaWNpZW50bHlMb25nQW5kU2VjdXJl
```

### 1.3.3 配置集群通讯录 (cluster.conf)
在两个节点的 `conf` 目录下，将 `cluster.conf.example` 重命名为 `cluster.conf`，并填入本机的 **真实局域网 IP**（不可使用 127.0.0.1）：
```text
192.168.x.x:8801
192.168.x.x:8802
```

## 1.4 配置本地 Nginx 负载均衡

由于微服务不能同时连接两个 IP，我们需要 Nginx 作为统一入口（80 端口）进行流量分发。

### 1.4.1 Nginx 配置实操
打开本地 Nginx 的 `conf/nginx.conf`，在 `http` 块内添加以下内容：

```conf
# 1. 定义 Nacos 集群上游
upstream nacos-cluster {
    server 127.0.0.1:8801;
    server 127.0.0.1:8802;
}

server {
    listen       80;
    server_name  localhost;

    # 2. 拦截 /nacos 请求并转发给集群
    location /nacos {
        proxy_pass http://nacos-cluster;
    }
}
```
修改后重启 Nginx。此时访问 `http://localhost/nacos` 即可进入管理后台。

## 1.5 微服务接入高可用集群

最后，修改 Spring Boot 项目的 `application.yml`，将服务注册地址指向 Nginx 入口。

```yaml
spring:
  application:
    name: bookservice
  cloud:
    nacos:
      discovery:
        # 指向 Nginx 的 80 端口，由其决定分发给 8801 还是 8802
        server-addr: 127.0.0.1:80
```

至此，高可用架构搭建完成。即使在 IDEA 中关闭其中一个 Nacos 实例，微服务依然能通过 Nginx 正常注册到另一个存活节点。

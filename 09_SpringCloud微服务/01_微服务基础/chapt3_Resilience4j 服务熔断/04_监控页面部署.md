## 1.1 父工程模块注册

首先，在项目根目录的 `pom.xml` 中，将新建的监控模块添加进去，以便进行统一的 Maven 构建：

```xml
<modules>
    <module>commons</module>
    <module>eureka_server</module>
    <module>user_service</module>
    <module>book_service</module>
    <module>borrow_service</module>
    <module>monitor_dashboard</module> </modules>
```

## 1.2 创建监控中心模块

在 `springcloud` 目录下新建一个名为 `monitor_dashboard` 的 Maven 模块。

### 1.2.1 导入依赖
在 `monitor_dashboard/pom.xml` 中添加服务端依赖：

```xml
<dependencies>
    <dependency>
        <groupId>de.codecentric</groupId>
        <artifactId>spring-boot-admin-starter-server</artifactId>
        <version>3.4.1</version> 
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
</dependencies>
```

### 1.2.2 配置文件
```yaml
# 路径：springcloud/monitor_dashboard/src/main/resources/application.yml
server:
  port: 8900
```

### 1.2.3 启动类
```java
// 路径：springcloud/monitor_dashboard/src/main/java/com/example/monitor/MonitorDashboardApplication.java
@EnableAdminServer
@SpringBootApplication
public class MonitorDashboardApplication {
    public static void main(String[] args) {
        SpringApplication.run(MonitorDashboardApplication.class, args);
    }
}
```

## 1.3 配置被监控微服务

我们需要让 `borrow_service`（借阅服务）主动向监控中心汇报数据。

### 1.3.1 添加监控与熔断依赖
```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-actuator</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-starter-circuitbreaker-resilience4j</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-aop</artifactId>
    </dependency>
    <dependency>
        <groupId>de.codecentric</groupId>
        <artifactId>spring-boot-admin-starter-client</artifactId>
        <version>3.4.1</version>
    </dependency>
</dependencies>
```

### 1.3.2 客户端配置
在 `borrow_service` 的配置文件中添加监控中心地址，并暴露所有监控端点：

```yaml
# 路径：springcloud/borrow_service/src/main/resources/application.yml
spring:
  boot:
    admin:
      client:
        url: http://localhost:8900 # 对应监控中心的端口

management:
  endpoints:
    web:
      exposure:
        include: '*' # 暴露包括 resilience4j 在内的所有端点
  endpoint:
    health:
      show-details: always # 必须开启，否则监控页面看不到熔断器的具体数值
```

## 1.4 监控数据查看与熔断实验

### 1.4.1 访问监控面板
启动所有服务后，打开浏览器访问：`http://localhost:8900`。在“应用墙”中可以看到 `borrowservice` 已上线。

![image-20230306230335020](https://s2.loli.net/2023/03/06/5rbCxLtR1e8DZAu.png)

### 1.4.2 观察正常流量
点击应用进入详情，在“健康” (Health) 菜单下可以看到 `circuitBreakers` 条目。调用几次借阅接口，成功计数会增加，状态显示为绿色的 **UP (CLOSED)**。

![image-20230306230402987](https://s2.loli.net/2023/03/06/UtcOjEfdnMGQ7ge.png)

### 1.4.3 模拟熔断
尝试关闭 `book_service`（图书服务），然后密集访问借阅服务。

![image-20230306230414273](https://s2.loli.net/2023/03/06/97by1FDirquwtv2.png)

由于依赖服务不可用，错误率会迅速攀升。当达到配置的失败率阈值后，监控页面会显示 `Circuit` 变为红色，状态更改为 **OPEN**。此时请求将不再发往图书服务，而是直接执行 Fallback 降级逻辑，实现对系统的保护。

![image-20230306230501543](https://s2.loli.net/2023/03/06/mrVf1qSsDXioIBc.png)

# 1. Hystrix 服务熔断

官方文档：<https://cloud.spring.io/spring-cloud-static/spring-cloud-netflix/1.3.5.RELEASE/single/spring-cloud-netflix.html#_circuit_breaker_hystrix_clients>

我们知道，微服务之间是可以进行相互调用的，那么如果出现了下面的情况会导致什么问题？

![image-20230306230121344](https://s2.loli.net/2023/03/06/dUvO3K8oWMZSVHr.png)

由于位于最底端的服务提供者E发生故障，那么此时会直接导致服务ABCD全线崩溃，就像雪崩了一样。

![image-20230306230128050](https://s2.loli.net/2023/03/06/dDMylZ5ejKoxAVF.png)

这种问题实际上是不可避免的，由于多种因素，比如网络卡顿、系统故障、硬件问题等，都存在一定可能，会导致这种极端的情况发生。因此，我们需要寻找一个应对这种极端情况的解决方案。

为了解决分布式系统的雪崩问题，SpringCloud 提供了熔断器组件。它就像家中的保险丝，当电流过载就会直接熔断，防止危险进一步发生。

我们来详细看看它的工作机制。

## 1.1 服务降级

服务降级并不会直接返回错误，而是提供一个补救措施（Fallback），正常响应给请求者。这样相当于服务依然可用，但服务能力有所下降。

要在项目中实现服务降级，需要遵循以下配置顺序：

### 1. 导入依赖

在“发起调用”的服务（消费者）的 `pom.xml` 中导入 Resilience4j 依赖。
**注意：** SpringBoot 3.x 配合 Resilience4j 时，底层强依赖 AOP，因此必须一并导入 AOP 依赖，否则注解将无法生效。

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-circuitbreaker-resilience4j</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
```

### 2. 配置文件设置

在 `application.yml` 中定义熔断和超时的具体规则。配置中的 `instances` 名称必须与代码中注解定义的 `name` 一一对应。

```yaml
resilience4j:
  # 1. 超时控制配置：定义请求多久没响应算作失败
  timelimiter:
    instances:
      borrow:
        timeout-duration: 3s # 超过3秒则触发降级
  
  # 2. 熔断器配置：定义什么时候真正“烧断保险丝”
  circuitbreaker:
    instances:
      borrow:
        sliding-window-type: COUNT_BASED     # 基于请求次数的滑动窗口
        sliding-window-size: 10              # 统计最近 10 次请求
        minimum-number-of-calls: 5           # 最小请求数：至少有 5 次请求才开始计算失败率
        failure-rate-threshold: 50           # 失败率阈值：达到 50% 时开启熔断
        wait-duration-in-open-state: 10s     # 熔断开启 10 秒后进入“半开”状态尝试恢复
```

### 3. 代码实现

在 Controller 层使用 `@CircuitBreaker` 注解指定备选方案。

**关键点：**
1. 备选方案（Fallback）的参数必须包含 `Throwable` 异常参数。
2. 备选方案必须使用 `public` 修饰符，以便 AOP 代理能够正确识别。
3. Service 层抛出的异常不要在内部 `try-catch` 吞掉，否则 Controller 无法感知错误。

```java
@RestController
public class BorrowController {

    @Resource
    BorrowService service;

    @io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker(name = "borrow", fallbackMethod = "onError")
    @RequestMapping("/borrow/{uid}")
    public UserBorrowDetail findUserBorrows(@PathVariable("uid") int uid){
        return service.getUserBorrowDetailByUid(uid);
    }
		
    // 备选方案：必须是 public，且参数末尾带有 Throwable
    public UserBorrowDetail onError(int uid, Throwable e){
        return new UserBorrowDetail(null, Collections.emptyList());
    }
}
```

# 1. 搭建认证服务器

## 1.1 当前项目版本说明

当前项目使用的是 Spring Boot 3 体系：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.12</version>
</parent>

<properties>
    <java.version>17</java.version>
    <spring-cloud.version>2023.0.1</spring-cloud.version>
    <spring-cloud-alibaba.version>2023.0.1.0</spring-cloud-alibaba.version>
</properties>
```

所以不能继续使用旧课程中 Spring Boot 2 / Spring Security 5 的 OAuth2 写法。

下面这些旧 API 在当前项目中不再适用：

```text
spring-cloud-starter-oauth2
WebSecurityConfigurerAdapter
@EnableAuthorizationServer
AuthorizationServerConfigurerAdapter
/oauth/token
/oauth/authorize
/oauth/check_token
```

Spring Boot 3 + Spring Security 6 应改用 Spring Authorization Server。

## 1.4 修改配置文件

配置文件放到 `D:\JetBrain IDEA\Project\SpringCloud_Ali\auth_service\src\main\resources\application.yml`。如果 `resources` 目录下还没有 `application.yml`，就新建这个文件：

```yaml
server:
  # 认证服务端口
  port: 8500
  servlet:
    # 给认证服务统一加前缀，最终端点会变成 /sso/oauth2/token
    context-path: /sso

spring:
  application:
    # 注册到 Nacos 的服务名
    name: auth-service
  cloud:
    nacos:
      discovery:
        # 本地 Nacos 地址
        server-addr: localhost:8848
```

这里的 `context-path: /sso` 仍然可以保留，用来避免多个本地服务都使用 `localhost` 时 Cookie 路径冲突。

## 1.5 编写认证服务器配置

新建认证服务器配置类，文件路径为 `D:\JetBrain IDEA\Project\SpringCloud_Ali\auth_service\src\main\java\com\example\authservice\config\AuthorizationServerConfiguration.java`。如果 `config` 包不存在，就在 `com.example.authservice` 下面新建 `config` 包：

```java
package com.example.authservice.config;


@Configuration
public class AuthorizationServerConfiguration {

    @Bean
    @Order(1) // 授权服务器过滤链优先级最高，先处理 /oauth2/** 等端点
    public SecurityFilterChain authorizationServerSecurityFilterChain(HttpSecurity http) throws Exception {
        // 应用 Spring Authorization Server 默认安全配置
        OAuth2AuthorizationServerConfiguration.applyDefaultSecurity(http);

        // 开启 OIDC 支持，会暴露 openid-configuration、userinfo 等相关能力
        http.getConfigurer(OAuth2AuthorizationServerConfigurer.class)
                .oidc(Customizer.withDefaults());

        // 未登录访问授权端点时，跳转到当前服务的 /login 页面
        http.exceptionHandling(exceptions -> exceptions
                .authenticationEntryPoint((request, response, authException) ->
                        response.sendRedirect(request.getContextPath() + "/login")));

        return http.build();
    }

    @Bean
    public RegisteredClientRepository registeredClientRepository() {
        RegisteredClient webClient = RegisteredClient.withId(UUID.randomUUID().toString())
                // 客户端 id，Postman 或业务服务申请 Token 时使用
                .clientId("web")
                // {noop} 表示明文密码，仅适合课堂演示
                .clientSecret("{noop}654321")
                // 支持 Basic Auth: Authorization: Basic base64(clientId:secret)
                .clientAuthenticationMethod(ClientAuthenticationMethod.CLIENT_SECRET_BASIC)
                // 支持表单提交 client_id/client_secret
                .clientAuthenticationMethod(ClientAuthenticationMethod.CLIENT_SECRET_POST)
                // 授权码模式，适合浏览器登录后换取 Token
                .authorizationGrantType(AuthorizationGrantType.AUTHORIZATION_CODE)
                // 刷新令牌模式，用 refresh_token 换新 access_token
                .authorizationGrantType(AuthorizationGrantType.REFRESH_TOKEN)
                // 客户端模式，适合服务调用服务
                .authorizationGrantType(AuthorizationGrantType.CLIENT_CREDENTIALS)
                // 授权码模式回调地址，请求 authorize 时必须保持一致
                .redirectUri("http://localhost:8201/login")
                // scope 会进入 Token，资源服务器可用 SCOPE_xxx 判断权限
                .scope("book")
                .scope("user")
                .scope("borrow")
                .clientSettings(ClientSettings.builder()
                        // true 表示授权码模式下会显示确认授权页面
                        .requireAuthorizationConsent(true)
                        .build())
                .build();

        // 演示环境使用内存保存客户端；真实项目一般放数据库
        return new InMemoryRegisteredClientRepository(webClient);
    }

    @Bean
    public JWKSource<SecurityContext> jwkSource() {
        // 授权服务器用私钥签发 JWT，资源服务器用公钥验签
        KeyPair keyPair = generateRsaKey();
        RSAPublicKey publicKey = (RSAPublicKey) keyPair.getPublic();
        RSAPrivateKey privateKey = (RSAPrivateKey) keyPair.getPrivate();

        RSAKey rsaKey = new RSAKey.Builder(publicKey)
                .privateKey(privateKey)
                // keyID 用来标识当前密钥，资源服务器按它找到对应公钥
                .keyID(UUID.randomUUID().toString())
                .build();

        JWKSet jwkSet = new JWKSet(rsaKey);
        return new ImmutableJWKSet<>(jwkSet);
    }

    private static KeyPair generateRsaKey() {
        try {
            KeyPairGenerator keyPairGenerator = KeyPairGenerator.getInstance("RSA");
            // 2048 位 RSA 是演示和常规场景里比较常见的选择
            keyPairGenerator.initialize(2048);
            return keyPairGenerator.generateKeyPair();
        } catch (Exception e) {
            throw new IllegalStateException(e);
        }
    }

    @Bean
    public AuthorizationServerSettings authorizationServerSettings() {
        // 使用默认端点：/oauth2/authorize、/oauth2/token、/oauth2/jwks 等
        return AuthorizationServerSettings.builder().build();
    }
}
```

说明：

- `RegisteredClientRepository` 相当于旧版中的 `ClientDetailsServiceConfigurer`。
- `RegisteredClient` 用来配置客户端 id、secret、授权模式、回调地址和 scope。
- 当前示例用 `{noop}654321` 是为了课堂测试方便，真实项目应使用加密后的 client secret。
- Spring Authorization Server 默认支持 `/oauth2/authorize`、`/oauth2/token`、`/oauth2/jwks`、`/oauth2/introspect` 等端点。

## 1.6 编写登录安全配置

新建登录与用户配置类，文件路径为 `D:\JetBrain IDEA\Project\SpringCloud_Ali\auth_service\src\main\java\com\example\authservice\config\SecurityConfiguration.java`。它和上面的 `AuthorizationServerConfiguration` 放在同一个 `config` 包中：

```java
package com.example.authservice.config;



@Configuration
public class SecurityConfiguration {

    @Bean
    @Order(2) // 普通登录过滤链，优先级低于授权服务器端点过滤链
    public SecurityFilterChain defaultSecurityFilterChain(HttpSecurity http) throws Exception {
        http
                .authorizeHttpRequests(authorize -> authorize
                        // 除授权服务器端点外，其他请求都需要登录
                        .anyRequest().authenticated())
                // 使用 Spring Security 默认登录页
                .formLogin(Customizer.withDefaults());

        return http.build();
    }

    @Bean
    public UserDetailsService userDetailsService() {
        UserDetails user = User.withUsername("test")
                // {noop} 表示明文密码，仅适合课堂演示
                .password("{noop}123456")
                .roles("USER")
                .build();

        // 演示环境把用户放内存；真实项目一般从数据库读取
        return new InMemoryUserDetailsManager(user);
    }
}
```

这里不再继承 `WebSecurityConfigurerAdapter`，而是通过 `SecurityFilterChain` 注册安全过滤链。

这里直接使用 Spring Security 默认登录页，浏览器访问授权地址时会自动跳转到登录页面。

## 1.7 测试客户端模式

启动认证服务后，请求地址改为新版：

```text
http://localhost:8500/sso/oauth2/token
```

Postman 中选择 `POST`，Authorization 使用 Basic Auth：

```text
Username: web
Password: 654321
```

Body 使用 `x-www-form-urlencoded`：

```text
grant_type=client_credentials  # 客户端模式，不需要用户登录
scope=book                     # 申请 book 这个资源权限
```

如果成功，会返回 access token。

## 1.8 测试授权码模式

浏览器访问：

```text
http://localhost:8500/sso/oauth2/authorize?response_type=code&client_id=web&scope=book%20user&redirect_uri=http://localhost:8201/login
```
![1.8.1](https://bsyimg.luoca.net/imgtc/20260524/67dc3267541dc2b165bc27a4b7e3fc9a.webp)
登录用户：

```text
username: test
password: 123456
```

确认授权后，浏览器会跳转到：

```text
http://localhost:8201/login?code=授权码
```

然后使用 Postman 请求 token：

```text
POST http://localhost:8500/sso/oauth2/token
```

Authorization 使用 Basic Auth：

```text
Username: web
Password: 654321
```

Body 使用 `x-www-form-urlencoded`：

```text
grant_type=authorization_code          # 使用授权码换取 Token
code=刚刚获取的授权码                   # 浏览器回调地址里的 code 参数
redirect_uri=http://localhost:8201/login # 必须和申请授权码时的 redirect_uri 一致
```

请求成功后会返回 access token 和 refresh token。

新版刷新令牌仍然请求 token 端点：

```text

```

Authorization 使用 Basic Auth：

```text

```

## 旧版内容说明

旧版 OAuth2 课程常见的 password 模式和 implicit 模式不建议继续作为当前项目主线内容：

- `password` 模式已经不推荐使用，现代 OAuth2 更推荐授权码模式配合 PKCE。
- `implicit` 模式也已经不推荐使用，前端应用同样应优先使用授权码模式配合 PKCE。
- 旧版 `/oauth/check_token` 对应新版的 token introspection 端点，一般是 `/oauth2/introspect`，并且需要客户端认证。

因此，当前项目中建议重点掌握三类模式：

```text
authorization_code
client_credentials
refresh_token
```

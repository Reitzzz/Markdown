## 1. 路线一：基于 OAuth2 Client 实现单点登录

如果**某个服务需要作为浏览器访问的 Web 客户端，让用户跳转到授权服务器登录，再回到当前服务**（这个服务本身面向浏览器用户，用户访问它时，如果还没登录，它不会自己完成账号密码校验，而是把用户重定向到统一的授权服务器去登录。登录成功后，授权服务器再把浏览器带回这个服务，由这个服务接住回调并建立自己的登录态），就使用 OAuth2 Client。

### 1.1 引入依赖

在需要作为浏览器访问的 Web 客户端，让用户跳转到授权服务器登录，再回到当前服务的后端服务的`pom.xml`中引入：
```xml
<!-- Spring Security 基础依赖，负责认证和授权过滤器链 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<!-- OAuth2 Client 依赖，用于授权码登录、跳转授权服务器、处理回调 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-client</artifactId>
</dependency>
```

### 1.2 配置客户端信息

以 `book_service` 或其他 Web 服务为例：

```yaml
server:
  port: 8201

spring:
  security:
    oauth2:
      client:
        registration:
          # registrationId，后面回调地址中的 {registrationId} 会替换成 web
          web:
            # 关联下面 provider.auth-server 这一组授权服务器配置
            provider: auth-server
            client-id: web
            client-secret: 654321
            # 浏览器登录场景使用授权码模式
            authorization-grant-type: authorization_code
            # OAuth2 Client 默认回调地址，必须和授权服务器 RegisteredClient 中注册的一致
            redirect-uri: "{baseUrl}/login/oauth2/code/{registrationId}"
            # openid 用于 OIDC 登录，book/user/borrow 是业务资源 scope
            scope:
              - openid
              - book
              - user
              - borrow
        provider:
          auth-server:
            # 授权服务器 issuer，当前 auth_service 配了 context-path: /sso
            issuer-uri: http://localhost:8500/sso
```

注意：`redirect-uri` 必须和授权服务器中 `RegisteredClient` 注册的地址一致。Spring Security OAuth2 Client 默认回调地址是：

```text
/login/oauth2/code/{registrationId}
```

如果使用上面的 `registrationId=web`，那么回调地址就是：

```text
http://localhost:8201/login/oauth2/code/web
```

此时授权服务器里也应该注册这个地址：

```java
.redirectUri("http://localhost:8201/login/oauth2/code/web")
```

如果仍然使用项目当前的：

```java
.redirectUri("http://localhost:8201/login")
```

则需要自定义 OAuth2 Login 的回调处理地址，不建议初学阶段这样做。

### 1.3 开启 oauth2Login

Spring Boot 3 不再使用 `@EnableOAuth2Sso`，而是通过 `SecurityFilterChain` 配置：

```java
@Configuration
public class SecurityConfiguration {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                // 所有请求都需要先登录
                .authorizeHttpRequests(authorize -> authorize
                        .anyRequest().authenticated())
                // 开启 OAuth2 登录，未登录时会跳转到授权服务器
                .oauth2Login(Customizer.withDefaults());

        // 构建 Spring Security 过滤器链，Boot 3 不再继承 WebSecurityConfigurerAdapter
        return http.build();
    }
}
```

访问受保护接口时，如果用户还没有登录，会跳转到授权服务器完成登录和授权。

### 1.4 获取当前登录用户

可以直接从方法参数中获取当前用户：

```java
@GetMapping("/me")
public Map<String, Object> me(@AuthenticationPrincipal OidcUser user) {
    // OIDC 用户信息会放在 claims 中，比如 sub、用户名等
    return user.getClaims();
}
```

如果没有启用 OIDC，也可以使用：

```java
@GetMapping("/me")
public Object me(Authentication authentication) {
    // 普通 OAuth2 登录时，可以直接查看当前认证对象
    return authentication;
}
```

## 2. 路线二：基于 Resource Server 实现资源服务

如果服务**只负责提供接口资源，不负责浏览器登录跳转** （这个服务不是给人直接看页面用的，而是给前端、其他服务、移动端调用 API 用的。它不处理“跳到登录页再回来”这种浏览器交互，只做一件事：检查请求里有没有合法的 Access Token，有就放行，没有就拒绝），就应该作为 Resource Server。客户端访问它时必须携带 Access Token。

### 2.1 引入依赖

在 `book_service`、`user_service`、`borrow_service` 这类资源服务模块中添加：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<!-- Resource Server 依赖，用于校验 Bearer Token、解析 JWT -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-oauth2-resource-server</artifactId>
</dependency>
```

### 2.2 配置 JWT 校验信息

推荐使用 `issuer-uri`：

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          # 资源服务器根据 issuer 自动发现 jwks_uri 等信息
          issuer-uri: http://localhost:8500/sso
```

也可以直接使用 JWK 地址：

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          # 直接指定授权服务器暴露的公钥地址，用于本地验签 JWT
          jwk-set-uri: http://localhost:8500/sso/oauth2/jwks
```
![2.2](https://bsyimg.luoca.net/imgtc/20260524/ce9d39f3c2a8576c11fbe6fb26e17acf.webp)

两者选一种即可。`issuer-uri` 会通过授权服务器的发现端点获取相关配置；`jwk-set-uri` 是直接告诉资源服务器去哪里拿公钥。

### 2.3 配置资源访问规则

Spring Boot 3 不再使用 `@EnableResourceServer` 和 `ResourceServerConfigurerAdapter`，改为：

```java
@Configuration
public class ResourceServerConfiguration {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
                .authorizeHttpRequests(authorize -> authorize
                        // 监控接口放行，避免健康检查也必须携带 Token
                        .requestMatchers("/actuator/**").permitAll()
                        // 其他接口要求 Token 中包含 book 这个 scope
                        .anyRequest().hasAuthority("SCOPE_book"))
                // 按 JWT 方式校验 Bearer Token
                .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));

        return http.build();
    }
}
```

如果只要求登录用户携带合法 Token，不区分 scope：

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
            .authorizeHttpRequests(authorize -> authorize
                    // 只要 Token 合法即可访问，不额外判断 scope
                    .anyRequest().authenticated())
            // 启用 JWT 资源服务器能力
            .oauth2ResourceServer(oauth2 -> oauth2.jwt(Customizer.withDefaults()));

    return http.build();
}
```

Spring Security 会把 JWT 中的 `scope` 或 `scp` 转换成 `SCOPE_xxx` 权限。例如授权服务器发放的 scope 包含 `book`，资源服务器中就可以使用：

```java
.hasAuthority("SCOPE_book")
```

### 2.4 携带 Token 访问资源

访问资源服务时，请求头需要携带：

```http
Authorization: Bearer access_token值
```
![2.4](https://bsyimg.luoca.net/imgtc/20260524/8e93323152497e93cb311255f3e2fee2.webp)
例如：

```bash
curl -H "Authorization: Bearer eyJ..." http://localhost:8201/book/1
```

不建议继续使用 URL 参数传递 Token：

```text
?access_token=xxx
```

这种方式容易泄露 Token，现代项目中一般使用 `Authorization` 请求头。

### 2.5 OpenFeign OAuth2 配置

服务间调用时，资源服务之间也需要传递 Token。旧版 OAuth2RestTemplate 已不适合 Spring Boot 3 项目。

Spring Cloud OpenFeign 新版配置前缀是 `spring.cloud.openfeign`，不是旧版 `feign`：

```yaml
spring:
  cloud:
    openfeign:
      oauth2:
        # 开启 OpenFeign 的 OAuth2 支持
        enabled: true
        # 指定使用哪一个 OAuth2 Client 配置去申请访问令牌
        clientRegistrationId: web
```

这种方式更适合服务以自己的客户端身份获取 Token，再调用下游服务。通常配合 `client_credentials` 模式使用。

对应 OAuth2 Client 配置示例：

```yaml
spring:
  security:
    oauth2:
      client:
        registration:
          web:
            provider: auth-server
            client-id: web
            client-secret: 654321
            # 服务调用服务时通常使用客户端凭证模式，不需要浏览器参与
            authorization-grant-type: client_credentials
            # 下游资源服务会根据这些 scope 判断访问权限
            scope:
              - book
              - user
              - borrow
        provider:
          auth-server:
            # 客户端凭证模式直接向 Token 端点申请访问令牌
            token-uri: http://localhost:8500/sso/oauth2/token
```

### 2.6 使用 RequestInterceptor 透传用户 Token

如果希望把用户请求中的 Token 原样传给下游服务，可以配置 Feign 拦截器：

```java
@Configuration
public class FeignTokenRelayConfiguration {

    @Bean
    public RequestInterceptor bearerTokenRelayInterceptor() {
        return template -> {
            // 从当前用户请求上下文中取出原始 HTTP 请求
            ServletRequestAttributes attributes =
                    (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();

            if (attributes == null) {
                return;
            }

            // 读取用户请求头中的 Authorization: Bearer xxx
            String authorization = attributes.getRequest().getHeader(HttpHeaders.AUTHORIZATION);
            if (StringUtils.hasText(authorization)) {
                // 调用下游服务时继续带上同一个 Token
                template.header(HttpHeaders.AUTHORIZATION, authorization);
            }
        };
    }
}
```

![2.6](https://bsyimg.luoca.net/imgtc/20260524/883af23a85d4e9c76f3f07aa03d20760.webp)

这种方式适合“用户访问 borrow_service，borrow_service 再调用 user_service / book_service，并沿用同一个用户 Token”的场景。
